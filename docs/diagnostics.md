# Diagnostics

Single-direction diagnostics validate the original source, conditionally
create a run-local prepared source copy for known compatibility fixes, and
then evaluate target parse/loadability, conformance, geometry, topology,
references and source-element mapping at the smallest traceable road, lanelet,
lane or regulatory element. These checks are delivered as one final report.

Diagnostics never repair target maps. When a source repair is applied during a
conversion run, the original source remains unchanged and the report records
the run-local prepared copy. `prepare-source` additionally lets users create a
prepared source at a user-selected path before conversion.

The five atomic public workflow profiles are implemented independently:

- `lanelet2_opendrive_diagnostics.py`
- `opendrive_lanelet2_diagnostics.py`
- `osm_lanelet2_diagnostics.py`
- `lanelet2_osm_diagnostics.py`
- `lanelet2_raster_diagnostics.py`

Shared report serialization and XML statistic collection are private runtime
components. Each public profile fixes the source/target formats and selects its
own geometry, topology and semantic checks.

Raster diagnostics open the generated products through GDAL/rasterio and
quantify lanelet relation coverage, visible index coverage, semantic-layer
population, occupancy consistency, raster dimensions/resolution, topology
sidecar completeness and drivable-grid connectivity. Each run also emits PNG
previews for direct visual inspection without an external GIS dependency.

Round-trip diagnostics compare A -> B -> A' without treating source IDs or
provenance as proof that a conversion succeeded. Each run emits one structured
`.json` report with a compact summary and traceable issue details.

The two composed workflows, OSM -> OpenDRIVE and OpenDRIVE -> OSM, retain the
evidence generated by both component conversions plus one concise composed
report index.
